01What is a graph

Arrays and linked lists are linear. Trees branch, but every node has exactly one parent. A graph drops both restrictions.

Definition. A graph G = (V, E) is a pair, where V is a finite non-empty set of vertices (also called nodes) and E is a set of edges. Each edge is a pair of vertices (u, v) with u, v ∈ V.

If the pair is unordered, the edge has no direction and the graph is undirected: (u,v) and (v,u) mean the same edge. If the pair is ordered, the edge runs one way and the graph is directed (a digraph): (u,v) means u → v only.

Two size symbols are used throughout this page and in every complexity result below:

SymbolMeaningRange
Vnumber of vertices—
Enumber of edges0 ≤ E ≤ V(V−1)/2 undirected, ≤ V(V−1) directed

That upper bound on E is the reason two different representations exist. When E is close to V² the graph is called dense; when E is closer to V it is sparse. Almost every real graph — road networks, social graphs, course prerequisites — is sparse.

02Terminology

These words appear in every question on this topic. The reference graph below is used for all the examples.

Reference graph — undirected, V = 6, E = 6

Adjacent (neighbour)
Two vertices joined by an edge. A and B are adjacent; A and D are not.
Incident
An edge is incident on the two vertices it joins. Edge A–B is incident on A and on B.
Degree — deg(v)
Number of edges incident on v. Here deg(A) = 2, deg(B) = 3, deg(D) = 1. In any undirected graph the degrees sum to 2E, because each edge is counted at both of its ends.
In-degree and out-degree
For a directed graph only. In-degree counts arrows arriving at v; out-degree counts arrows leaving. A vertex with in-degree 0 is a source; out-degree 0 makes it a sink.
Path
A sequence of vertices where each consecutive pair is joined by an edge, for example A – B – E – F. Its length is the number of edges, here 3.
Simple path
A path with no repeated vertex.
Cycle
A path of length ≥ 1 that starts and ends at the same vertex, with no other repeats. A – B – E – F – C – A is a cycle. A graph with no cycle is acyclic.
Connected
An undirected graph is connected if a path exists between every pair of vertices. If not, it splits into connected components.
Strongly connected
A directed graph where a directed path exists from every vertex to every other vertex. Weaker than it sounds: direction matters, so a digraph can look connected on paper and still fail this.
Subgraph
A graph whose vertices and edges are all drawn from another graph.
Complete graph — Kn
Every pair of distinct vertices is joined. It has n(n−1)/2 edges, the maximum possible.
Weighted graph
Each edge carries a numeric cost, distance or capacity. Needed by shortest-path algorithms; plain DFS and BFS ignore weights entirely.
Self-loop and parallel edges
An edge from a vertex to itself, and two edges joining the same pair. A graph with neither is called simple, which is what is assumed here.

03Types of graphs

Four distinctions cover almost every exam question.

DAG — directed acyclic graph. A digraph with no directed cycle. This is the only kind of graph on which a topological sort exists, and section 7 depends on it. Every tree is a DAG; not every DAG is a tree, because a DAG vertex may have several parents.

04Representation of graphs

A graph is an abstract object. Before any algorithm can run, it must be stored. There are two standard structures, and the choice between them is a space-versus-lookup trade.

Click any 1 in the matrix to highlight that edge.

Adjacency matrix

Adjacency list

Adjacency matrix

A V × V array where M[i][j] = 1 if an edge runs from vertex i to vertex j, and 0 otherwise. For a weighted graph, store the weight instead of 1 and use ∞ or 0 for absence.

In an undirected graph the matrix is always symmetric about the main diagonal, because every edge is recorded twice. In a directed graph it generally is not — switch the selector above and watch the symmetry break.

Adjacency list

An array of V lists. The list at index u holds exactly the vertices adjacent to u. An undirected edge u–v appears twice, once in each list; a directed edge appears only in the list of its source.

Edge list

The simplest of the three: just store all E pairs. Space is O(E), but answering "is u adjacent to v?" needs a scan of every edge, so it is used mainly as an input format and by algorithms that process edges in bulk, such as Kruskal's.

Which to choose. Use the adjacency list for sparse graphs, which is nearly always, and whenever the algorithm iterates over neighbours — DFS, BFS, Dijkstra, topological sort. Use the adjacency matrix for dense graphs, or when the program constantly asks whether one specific edge exists, or for algorithms defined on matrices such as Floyd–Warshall.

05Depth First Search

Go as deep as possible along one branch. Only when a vertex has no unvisited neighbour left do you back up and try the next option.

Definition. DFS visits a start vertex, marks it, then recursively visits any unvisited neighbour. When every neighbour of the current vertex has been visited, DFS backtracks to the vertex it came from. It uses a stack — either an explicit one, or the recursion call stack.

Algorithm

DFS(G, u):
    mark u as visited
    add u to the traversal order
    for each neighbour v of u:          // in some fixed order
        if v is not visited:
            DFS(G, v)                   // go deeper
    // no neighbour left: return, i.e. backtrack

MAIN(G):
    mark all vertices unvisited
    for each vertex u in V:             // handles disconnected graphs
        if u is not visited:
            DFS(G, u)

The outer loop in MAIN matters. One call to DFS reaches only the vertices connected to the start; the loop restarts it on any vertex left untouched, so every component is covered.

Properties

  • Each vertex is marked visited exactly once, so it is expanded once.
  • The edges it uses to reach new vertices form a DFS tree; the rest are back, forward or cross edges.
  • Finding a back edge — an edge to a vertex still on the recursion stack — proves the graph contains a cycle. This is the standard cycle-detection test.
  • Other uses: connected components, strongly connected components, topological sort, maze and puzzle solving.

06Breadth First Search

Visit everything one step away, then everything two steps away, and so on. The traversal expands in rings around the start vertex.

Definition. BFS visits the start vertex, then all of its neighbours, then all of their unvisited neighbours, level by level. It uses a queue, which is first-in first-out — the only structural difference from DFS.

Algorithm

BFS(G, s):
    mark all vertices unvisited
    create empty queue Q
    mark s visited                      // mark on ENQUEUE, not on dequeue
    enqueue s into Q
    while Q is not empty:
        u = dequeue(Q)
        add u to the traversal order
        for each neighbour v of u:
            if v is not visited:
                mark v visited
                enqueue v into Q
Mark on enqueue, not on dequeue. If a vertex is marked only when it comes out of the queue, it can be pushed several times before that happens — once by each neighbour that sees it. The traversal still finishes, but the queue can grow far beyond V and duplicates get processed. This is the single most common BFS bug.

Properties

  • In an unweighted graph, BFS finds the shortest path from the start to every reachable vertex, measured in number of edges. DFS does not.
  • The vertices come out grouped by level: distance 0, then 1, then 2, and so on.
  • Other uses: shortest hop count, testing whether a graph is bipartite, finding connected components, peer-to-peer and crawler search.

07Topological sort

Given a set of tasks where some must come before others, produce one valid order to do them all.

Definition. A topological sort of a directed acyclic graph G = (V, E) is a linear ordering of all vertices such that for every directed edge u → v, vertex u appears before vertex v in the ordering.

Two facts follow immediately, and both are common one-mark questions:

  • A topological sort exists if and only if the graph is a DAG. A cycle u → v → u would require u before v and v before u at the same time.
  • It is usually not unique. Any two vertices with no directed path between them may be ordered either way.

Kahn's algorithm — the in-degree method

TOPOSORT(G):
    compute in-degree of every vertex
    Q = all vertices with in-degree 0
    order = empty list
    while Q is not empty:
        u = dequeue(Q)
        append u to order
        for each neighbour v of u:      // each edge u -> v
            in-degree[v] = in-degree[v] - 1
            if in-degree[v] == 0:
                enqueue v into Q
    if order contains fewer than V vertices:
        report "graph has a cycle"
    else:
        return order

The idea is simple: a vertex is ready when nothing still points at it. Removing a vertex removes its outgoing edges, which may make its successors ready in turn.

The DFS method

The alternative runs a full DFS and pushes each vertex onto a stack after all of its descendants finish. Popping the stack gives a topological order.

TOPOSORT-DFS(G):
    mark all vertices unvisited
    S = empty stack
    for each vertex u in V:
        if u is not visited:
            VISIT(u)
    return S popped from top to bottom

VISIT(u):
    mark u visited
    for each neighbour v of u:
        if v is not visited:
            VISIT(v)
    push u onto S                       // after the subtree is finished

Both methods run in O(V + E). Kahn's is easier to trace by hand and detects cycles naturally through the final count; the DFS version needs no in-degree array but requires an extra colour or on-stack flag to report a cycle.

Worked reading of the example. Treat the vertices as subjects and the arrows as "must be passed before". A vertex with in-degree 0 is a subject with no pending prerequisite, so it can be taken now. The algorithm repeatedly takes such a subject and relaxes the requirements it unlocks.

08Complexity, and how to derive it

Do not memorise the table. Each result comes from one counting argument, which is what a viva will ask for.

Why traversals cost O(V + E)

Using an adjacency list, take DFS or BFS and count two things separately.

  • Vertices. The visited flag guarantees each vertex is expanded exactly once. Expanding one vertex costs a constant amount of bookkeeping. Total: O(V).
  • Edges. When a vertex is expanded, its whole adjacency list is scanned once. Summing over all vertices, the total work is Σ deg(u) = 2E for an undirected graph, or E for a directed one. Total: O(E).

Adding them gives O(V + E). The V term cannot be dropped, because a graph with no edges still requires all V vertices to be initialised and checked.

Using an adjacency matrix the edge count changes. Finding the neighbours of a vertex means scanning a full row of length V, whether or not the entries are zeros. That is V work per vertex, giving V × V = O(V²) regardless of how few edges exist.

The worst cases are different in shape even though the bound is the same. DFS reaches O(V) stack depth on a long chain A → B → C → …, where the recursion never returns until the end. BFS reaches O(V) queue length on a star, where one vertex enqueues every other vertex at once.

The same algorithms in the AI search model

Courses on artificial intelligence state these costs differently — DFS as O(bm) time and O(b·m) space, BFS as O(bd) for both. Neither statement contradicts the table above. They measure the same algorithms against a different kind of input.

Data structure modelAI search model
InputA graph already stored in memoryA state space generated on demand
Size known in advanceYes — V and E are givenNo, and possibly infinite
ParametersV, Eb, d, m
Visited setAlways maintainedOften absent (tree search)

Here b is the branching factor, the number of successors per state; d is the depth of the shallowest goal; and m is the maximum depth of the space.

The two time bounds are the same statement

A tree with branching factor b explored to depth d holds

V = 1 + b + b² + … + bd = O(bd)

nodes, and a tree has E = V − 1 edges. Substituting into O(V + E) gives O(bd). One formula is written in terms of the structure you stored, the other in terms of the shape of the space you are generating.

Careful with the DFS exponent. DFS time is O(bm), not O(bd). DFS drives one branch to the bottom, so it can spend bm work on a deep branch before ever reaching a goal that sits at depth d. Since m ≥ d, and m may be infinite, this is strictly worse than BFS. It is also why DFS is not complete in an infinite space while BFS is.

Why the space bounds diverge

In the data structure model both traversals carry a visited array of size V. That term dominates, so both land on O(V) and the difference between a stack and a queue never shows up in the bound.

In tree search there is no visited array — states are generated when needed and discarded. Space is then the frontier alone, and the stack-versus-queue difference becomes the only thing that matters.

BFS frontier

An entire level is held at once. With b = 3 at depth 2 that is bd = 9 nodes in memory, growing exponentially. BFS runs out of memory long before it runs out of time.

DFS frontier

One path plus the unexpanded siblings at each level: m + (b−1)m = b·m, here 6 nodes. The dashed nodes are never generated at all. Linear, not exponential.

Property (tree search)DFSBFS
TimeO(bm)O(bd)
SpaceO(b·m)O(bd)
CompleteNo — can descend foreverYes, if b is finite
OptimalNoYes, when every step costs the same
Practical limitTimeMemory

The two weaknesses are complementary, which is exactly what iterative deepening exploits: run a depth-limited DFS for limit 0, 1, 2, … until the goal appears. It keeps the O(b·d) space of DFS and the completeness and optimality of BFS, at O(bd) time — the repeated work costs only a constant factor, because the last level dominates the sum.
